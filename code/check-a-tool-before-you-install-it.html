Check a tool before you install it

A techdom tool runs on your side of the screen, next to your sign-ins and your saved card. Ten minutes of checking before you install it shows what it can read, what it sends and whether you can stop it.

A ten-minute check

Do the steps in order. If you can’t do one, that’s your answer.

Ten-minute check

  1. 1

    Find the maker. A maker with a history you can check counts, and a persona or a handle counts too. A tool from someone with no history at all has already failed.

  2. 2

    Open the permission list and the site list. Write down every line you can’t explain.

  3. 3

    List the addresses it talks to and find out who runs each one.

  4. 4

    Find the updater. Can it fetch and run new files, and who decides when?

  5. 5

    Check the defaults: does it start switched off? Does it show a running total? Is there a limit you set?

  6. 6

    Test the stop in every state: idle, running, locked, just after a payment. A stop that fails in one state is a defect.

  7. 7

    Compare the file you got with the fingerprint the maker published.

  8. 8

    Try it in a virtual machine or a fresh browser profile with none of your sign-ins.

Code you can run

Three short scripts show the idea. Each reads made-up data, opens no network connection and changes nothing on your computer.

Three small checks

Files

manifest_check.py

# manifest_check.py - read an extension manifest the way a stranger would, before installing.
# It reads two invented manifests that sit inside this file. It opens no file and no network.

SAMPLES = {
    "tight": {
        "manifest_version": 3,
        "name": "Example fan tool",
        "permissions": ["storage", "alarms"],
        "host_permissions": ["https://shop.example.test/*"],
        "content_scripts": [{"matches": ["https://shop.example.test/*"], "js": ["main.js"]}],
    },
    "wide": {
        "manifest_version": 3,
        "name": "Example wide tool",
        "permissions": ["storage", "tabs", "cookies", "webRequest", "scripting"],
        "host_permissions": ["<all_urls>"],
        "content_scripts": [{"matches": ["*://*/*"], "js": ["main.js"]}],
        "update_url": "https://updates.example.test/feed.xml",
    },
}

RISKY = {
    "tabs": "sees the address of every tab",
    "cookies": "reads and writes cookies",
    "webRequest": "sees every request",
    "scripting": "injects code into pages",
    "history": "reads browsing history",
    "nativeMessaging": "talks to a program on the computer",
    "clipboardRead": "reads the clipboard",
}
BROAD = {"<all_urls>", "*://*/*", "http://*/*", "https://*/*"}


def review(manifest):
    findings = []
    for permission in manifest.get("permissions", []):
        if permission in RISKY:
            findings.append("permission " + permission + ": " + RISKY[permission])
    patterns = list(manifest.get("host_permissions", []))
    for script in manifest.get("content_scripts", []):
        patterns += script.get("matches", [])
    for pattern in sorted(set(patterns)):
        if pattern in BROAD:
            findings.append("site access " + pattern + ": every website")
    if "update_url" in manifest:
        findings.append("it updates itself from " + manifest["update_url"])
    return findings


for name, manifest in SAMPLES.items():
    findings = review(manifest)
    if findings:
        print(name, "->", len(findings), "finding(s) to explain before installing")
    else:
        print(name, "->", "no broad access found (the code is still unread)")
    for line in findings:
        print("  -", line)

host_report.py

# host_report.py - group a list of request addresses by host and label each host,
# to answer "who does this page or tool talk to?" before trusting it.
# The addresses are invented and sit in this file. Nothing is fetched.
from collections import Counter

KNOWN = {
    "app.example.test": "the tool's own server",
    "cdn.example.test": "the tool's own server",
    "metrics.tracker.test": "analytics",
}

requests = [
    "https://app.example.test/page",
    "https://app.example.test/api/items",
    "https://cdn.example.test/img/1.png",
    "https://cdn.example.test/img/2.png",
    "https://metrics.tracker.test/collect",
    "https://mystery.host.test/x.js",
]


def host_of(address):
    return address.split("//", 1)[1].split("/", 1)[0]


counts = Counter(host_of(address) for address in requests)
for host, count in counts.most_common():
    print(count, "|", host, "|", KNOWN.get(host, "UNKNOWN: find out who runs it before trusting it"))

pinned_hash.py

# pinned_hash.py - compare a file against the fingerprint its author published.
# The "file" is a few bytes inside this script, so nothing is downloaded or opened.
import hashlib

published = hashlib.sha256(b"the file the author released").hexdigest()


def matches(data):
    return hashlib.sha256(data).hexdigest() == published


for label, data in [
    ("the file you got, same bytes", b"the file the author released"),
    ("the file you got, one byte added", b"the file the author released!"),
]:
    print(label, "->", "same as published" if matches(data) else "different: do not run it")

Outputpython pinned_hash.py

the file you got, one byte added -> different: do not run it

The fingerprint in the last script is computed inside it. In real life you copy it from the maker’s page and compare.

They show a method. They don’t give a verdict. A manifest check can’t see what the code does, and a matching fingerprint only proves you hold the file the maker published. Vivian’s field notesFirst-hand experience, not a study.

What a check can’t tell you

A verdict has two parts: what the check found, and what it didn’t cover. Vivian’s field notesFirst-hand experience, not a study.

Words for a verdict

  1. 1

    Malicious today

    The tool does harm now. Only say this after reading the whole source, and with the evidence. Vivian’s field notesFirst-hand experience, not a study.

  2. 2

    Not malicious today, able to become so with one update

    Nothing harmful runs now, but an update could change that, for example when the updater can fetch any file and your sign-ins sit on the same computer. Serious, but not malware. Vivian’s field notesFirst-hand experience, not a study.

  3. 3

    Harmless in code, unsafe in use

    Nothing hidden is harmful, but the defaults expose you: a machine identifier sent from your names, a safety-wordsafety wordA word agreed when consent is given that anyone can use to stop the play at once. It stops play between people, and the other person stops, answers calmly and doesn’t argue. or quick-exitquick exitA button, shortcut or menu entry that ends a tool or a remote session instantly and at no cost. Every tool that acts for a sub needs one that works in every state, and a tool without one isn’t safe. off by default. Vivian’s field notesFirst-hand experience, not a study.

  4. 4

    Not checked

    You didn’t read it, or couldn’t. Treat it as unsafe for any computer that holds your sign-ins. Vivian’s field notesFirst-hand experience, not a study.

What they say or doThe counter

If a tool you doubt is installed

  1. 1

    Stop it. Close the program, or turn the computer off. That always works.

  2. 2

    Remove it, and remove its browser extension too.

  3. 3

    Sign out everywhere it could reach, then change those passwords from a different computer.

  4. 4

    Check your order history and bank statement for sends you didn’t choose.

  5. 5

    Set a limit or an alert at your bank.

  6. 6

    If money left that you didn’t mean to send, go to If you already sent. If stopping feels hard, go to Where to get help.

  1. Question 1 of 4A tool asks to read and change your data on every website. What’s the first thing to do?

    Answer. Ask whether it can be limited to the one site it serves, and walk away if not. Access to every website is the widest access a tool can ask for. Narrow it or leave.

    Answer. It disables the extension until you accept the new permission. Chrome disables the extension until the user accepts. VerifiedChecked against the original source.Permission warnings (Chrome for Developers, extensions documentation) (opens in a new tab) Accessed 3 November 2026.

    Answer. Nothing obvious was found in the part that was read. A summary covers the part that was read. It can’t see what’s hidden or what an update may add.
